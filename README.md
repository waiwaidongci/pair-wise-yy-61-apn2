# pair-wise-yy-61 航空器定检工作包执行与放行审阅平台

支持工卡依赖、测量值容差校验、离线暂存、冲突提交提示、分阶段签字、版本差异和放行锁定。超差项目必须由授权人员处理后才能继续。

## 时寿件寿命账（前起落架拆换）

工卡 `CARD-09`、时寿件履历、阶段签字与放行基线接成一本"寿命账"，入口为侧边栏「时寿件寿命账」：

- **装机冻结 / 拆下固化**：新件装机时冻结当前机身循环；旧件拆下时按 `当前循环 − 装机冻结循环` 固化本段消耗，回写工卡。
- **三本账各算各的**：机身循环账（FC）、件履历账（R 版本）、放行基线（锁定时只读快照）独立维护；循环或履历变化只重算**当前装机件**，已拆件保留固化原值。
- **签字依赖失效**：循环入账、履历修正或拆换入账后，已签署的「适航」「放行」阶段自动置为已失效（带原因，需重签）；机械/系统/动力不受影响。
- **先到占用，后到留冲突**：两名技术员同时提交同一位置拆换时，mock 服务端按位置在途加锁；先到成功，后到收到 409 并在「占用与冲突」面板留痕，不覆盖已占用件、不产生草稿。
- **失败保留草稿 + 幂等重试**：离线或服务端 500 时草稿（含唯一事件号）保留；恢复后按**原事件号**重试，服务端幂等返回，防重复入账；乐观锁过期（R 版本落后）则提示刷新对账，不留草稿。
- **放行基线**：无待授权项、无待重试草稿、装机件剩余循环 ≥ 500 FC 且五阶段签署齐全方可锁定；锁定后循环/拆换/履历写入被阻止，基线与当前账的差异在「放行审阅 → 寿命账基线」对照。

## 技术栈

React、Fluent UI、Redux Toolkit、React Router、RTK Query、Vite、TypeScript。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62061`。工卡草稿、寿命账、冲突与审计操作保存在 `localStorage`。

```bash
npm run build
npm test        # 寿命账规则 + 服务端并发/幂等冒烟测试
```
